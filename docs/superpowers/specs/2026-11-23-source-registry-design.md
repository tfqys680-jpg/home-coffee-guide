# 出典を先に用意してから書く（出典リスト＋自動調査）設計

日付: 2026-11-23

## 目的と理由

2026-11-23 の初回実行で、記事「hand-drip-basic-steps」が出典不足で保留になった。原因は次の3つ。

1. ChatGPT はネットを見られないため、出典URLを記憶から推測している。今回は2件とも外れた（Starbucks は404、NCA は旧URLが数値のない一覧ページへ転送）。
2. 転送先が別ページでも「取得できた」と扱っている。
3. ChatGPT は出典本文を見ないまま書き、数値の裏付けは後から Claude が削るだけになっている。

実際には NCA の正しいハンドドリップ解説（aboutcoffee.org/brewing/pour-over-coffee/）に「粉1gに湯13〜16g」「93±3℃」「2〜4分」「蒸らし30〜45秒」が載っている。使える出典はあるのに、たどり着けていない。

運営者の完成条件は「機械チェックが全部通る／競合と並べて遜色ない／Googleに載る／放置で回り続ける」。この変更で、数値の裏付けがある記事を放置で出し続けられるようにする。

## 目標・やらないこと・やってはいけないこと

- 目標: 記事を書く前に、取得して中身を確かめた出典（2件以上）をそろえ、その本文を ChatGPT に渡して書かせる。出典がそろわないテーマは書かずに次のテーマへ回す。
- やらないこと: 品質ゲート（tools/quality）や審査の基準は変えない。ship.sh・ワークフローの流れは変えない。
- やってはいけないこと: 基準を緩めて通すこと。個人ブログ・通販・まとめサイトを出典にすること。取得できていない出典を「確認済み」と扱うこと。

## 方式の比較（採用: B）

| 案 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| A | テーマごとの出典リストを人が用意し、書く前に取得して本文を渡す | 確実・安い | リストのテーマ（10件、週2本で約5週間）を使い切ると止まる |
| **B** | A＋リストにないテーマは Claude の Web検索（信頼できるドメインに限定）で候補を探し、取得確認できたものだけ使う | 放置で回り続ける | APIの費用が少し増える。仕組みがやや複雑 |
| C | ChatGPT に Web検索させて書かせる | 実装が軽い | 書き手が自分で出典を選ぶ。出典の質を絞りにくい |

運営者が B を選んだ（2026-11-23）。

## 設計

### 出典リスト `docs/sources.json`

```json
{
  "hand-drip-basic-steps": [
    {"title": "National Coffee Association「Pour-Over Coffee」", "url": "https://www.aboutcoffee.org/brewing/pour-over-coffee/", "note": "粉と湯の比率・湯温・接触時間・蒸らし", "found_by": "manual"}
  ]
}
```

- キーはキューの slug。`found_by` は `manual`（人が登録）か `auto`（自動調査で見つけて取得確認できたもの）。
- キューの10テーマ分は、実装時に Claude Code が調べて登録する（各2〜4件。数値や定義が本文に載っていることを確かめたURLのみ）。
- 自動調査で確認できた出典は `auto` として書き戻す（再実行や運営者の確認に使う）。

### 1回の実行の流れ（pipeline.py）

1. 「待機」のテーマを選ぶ（今と同じ。空なら補充）。
2. **出典をそろえる**: 出典リストのURLを取得・確認 → 2件未満なら Claude の Web検索で候補を探して取得・確認 → それでも2件未満なら、そのテーマを「出典不足(日付)」にして次の「待機」テーマへ（1回の実行で最大3テーマまで試す）。
3. ChatGPT に、確認済み出典の一覧と本文抜粋を渡して書かせる。「sources にはこの一覧のURLだけを使う」と指示する。
4. 審査・品質ゲート・機械検証は今と同じ。加えて、記事の sources に一覧にないURLがあれば不合格にする。
5. 3テーマとも出典がそろわなければ、記事は書かずに結果を `blocked` で返す（キューの変更をコミットし、ship.sh が保留として知らせる）。

### 出典の取得確認（fetch_source）

- 転送されて別のページに着いたものは「確認できない」とする（http→https、www の有無、末尾の / の違いは同じページとみなす）。
- 本文は `<main>` か `<article>` があればその中を優先して抜き出す（メニューや足回りで抜粋の枠を使い切らないため）。抜粋の上限は今と同じ 12,000 字。
- それ以外（200以外・PDF・本文200字未満は除外）は今と同じ。

### 自動調査（Claude の Web検索）

- Anthropic Messages API の `web_search_20250305` ツールを使い、`allowed_domains` で検索先を `config.json` の `source_domains` に限る。`max_uses` は5。
- `source_domains` の初期値は、NCA（aboutcoffee.org・ncausa.org）、SCA（sca.coffee）、全日本コーヒー協会（ajca.or.jp）、国際コーヒー機関（ico.org）、日米の公的機関（FDA・農林水産省・厚生労働省・食品安全委員会・消費者庁など）。運営者が編集できる。
- Claude には「数値・条件・定義が本文に載っているページを、テーマの論点ごとに探す」と指示し、JSON（title・url・note）で候補を返させる。パイプラインが自分で取得して確かめたものだけを使う。
- モデルは ANTHROPIC_MODEL をそのまま使う。

### キュー

- `hand-drip-basic-steps` を「待機」に戻す。
- 新しい状態「出典不足(日付)」を追加する。運営者が出典リストにURLを足して「待機」に戻せば再挑戦する。

### テスト（APIと取得はモック）

- 既存テストのモック（openai_N / claude_N / sources.json）を新しい流れに合わせる。自動調査は research_N.json で返す。
- 追加するテスト:
  - 出典リストのURLが取得確認され、ChatGPT への依頼に本文抜粋が入る
  - 出典リストが足りないテーマは自動調査を行い、確認できた出典を `auto` として書き戻す
  - 出典がそろわないテーマは「出典不足」になり、次のテーマで記事ができる
  - 3テーマとも出典がそろわなければ記事を書かずに blocked
  - 記事の sources に一覧にないURLがあれば保留
  - 別ページへの転送を「確認できない」と判定する（単体テスト）
- `bash tools/verify.sh` が通ること。

### ドキュメント

- README の「自動記事の流れ」「運用」に、出典リストと「出典不足」の扱いを書き足す。

## 実装者に任せること

- 各テーマに登録する具体的なURL（上の基準を満たすもの）
- プロンプトの細かい言い回し
- `source_domains` の具体的なドメイン（上の方針の範囲で）

## 制約

- 外部ライブラリなし（Python標準ライブラリのみ）。
- 作業環境からは多くの外部サイトに直接つながらないため、登録するURLは Web取得ツールで中身を確かめる。GitHub Actions 上の取得が失敗した場合は自動調査に回る。
