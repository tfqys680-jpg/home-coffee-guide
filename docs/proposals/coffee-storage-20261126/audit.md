## 数値以外の修正

- 「コーヒーの袋は多くの場合、賞味期限」という頻度の一般化は、既存[2]の取得本文から確認できないため削除した。英語の best-by date と日本の表示を無条件に同一視しない。
- 古い豆を「危険より風味の問題」とする見出しは、安全判断を単純化するため変更した。カビが見えなければ安全、と読む余地を減らした。
- 冷凍から出した小袋を常温保存する案内は、温度を戻す手順の出典がないため、そのまま一般的な手順として案内しない。凍ったまま挽けるかも断定しない。
- 日付管理・普段用と予備の分け方は、当サイトの工夫として説明。数字を漢数字に変えて機械判定を回避する修正は行っていない。「1回に1袋」の削除は、出典由来の数値でないという内容面の判断。
- 早見表、FAQ、チェックリスト、内部リンク、基本構成を保持した。原稿は `article.md`、記事本体JSONは `article.json`。公開用itemのラッパーやPASSの審査記録は付けていない。

## 生成・審査の改善差分

1. 生成側の「段落の末尾に出典」という例を、「根拠となる同じ文の句点前に出典」へ変更。結論、FAQ、例、表、チェックリストにも適用する。
2. 未確認の数値を曖昧語や漢数字へ置き換えず、根拠がある具体的な目安と前提を保持する。根拠不足は削除・未確認表示とし、編集提案を別の文へ分ける。
3. 審査側は sources.note を証拠に使わず、取得本文との照合を要求。修正の位置・分類・根拠の箇所・対応を issues に記録する。
4. 通常審査の入力にも、現行の品質診断と全未出典文の候補を渡す。従来は通常審査の後に品質判定し、REVISEのまま上限に達すると、品質修正の追加ループへ進まない。このため、通常審査の最初から機械診断を見せる。
5. `article_quality.py`、閾値、必須出典数、審査回数上限、PASS必須、BLOCK/REVISEの保留扱いを維持する。追加処理は診断専用で、出典を補完せず原稿も変更しない。通常審査の各回に決定論的評価を追加するだけで、外部AI呼び出し回数は増やさない。

差分はZIP内の `changes.patch`。変更するコードは `tools/auto-publish/prompts.py` と `pipeline.py`、テストは既存2ファイルに追加している。保存記事は公開用ディレクトリへ追加せず、`docs/proposals/coffee-storage-20261126/` に置く。
