# 競合比較（合格条件 B1・B2 の判定）

合格条件は `evals/home-coffee-guide.md` の B。自動パイプラインの審査は Claude の知識による自己点検なので、ここで実際の検索結果と比べて確かめる。

## 対象を決める

- slug の指定があればその記事。なければ `content/articles/*.json` のうち `docs/competitor/<slug>.md` がない記事、または90日以上たったもの。
- 記事JSONの `main_kw`（主キーワード）、`article.sections` の見出し、表、`pipeline.coverage` を読む。

## 手順

1. 主キーワードで WebSearch する。通常の記事ページの上位3件を選ぶ（通販の商品ページ、動画、Q&Aサイト、自サイトは除く）。
2. 3件それぞれを WebFetch し、見出しと扱っている論点、表・写真・動画・専門家の解説など独自の要素を自分の言葉でメモする。競合の文章をコピーしない。
3. 論点ごとに「上位3件のうち何件が扱っているか」と「この記事が扱っているか」の表を作る。
4. 判定する。
   - B1: 上位3件のうち2件以上が扱う論点を、この記事がすべて扱っていれば ○。
   - B2: 上位3件のどれにもない要素（出典つきの早見表・比較表、症状別の表など）がこの記事に1つ以上あれば ○。
5. `docs/competitor/<slug>.md` に下の形式で書く。
6. × があれば、記事JSONを直す。
   - 足す内容は出典で裏付けられることだけ。出典を足したら `sources` に追加し、本文に [n] を付ける。
   - 架空の体験・試飲・テスト、健康効果の断定、特定商品の推奨は書かない（CLAUDE.md）。
   - 裏付けが取れない論点は足さず、レポートに「扱わない理由」を書く。
   - `updated` を今日の日付にし、`python3 tools/site/build.py` と `bash tools/verify.sh` を通してから、ブランチ＋PRで出す。
7. 依頼者に、○×、直したこと、人が見て判断してほしいこと（B3: 並べて読んで見劣りしないか）を短く伝える。

## レポートの形式（docs/competitor/<slug>.md）

```markdown
# 競合比較: <記事タイトル>
調べた日: YYYY-MM-DD / 主キーワード: <main_kw>

| 順位 | ページ | 特徴（自分の言葉で） |
|---|---|---|
| 1 | [タイトル](URL) | ... |

| 論点 | 上位で扱う件数 | この記事 |
|---|---|---|
| ... | 3/3 | ○（H2「...」） |

- B1（上位2件以上が扱う論点をすべて扱う）: ○/×
- B2（上位にない独自の要素）: ○/× — <要素>
- 直したこと: ...
- 扱わない論点と理由: ...
```

## 注意

- 検索結果は日や場所で変わるので、調べた日を必ず書く。
- 引用は1件につき15語未満の短いものに限り、基本は自分の言葉でまとめる。
